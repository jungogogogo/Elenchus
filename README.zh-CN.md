# Elenchus

[English](./README.md) | 中文

你不是没有想法，是没有选项可以反应。这个 Claude Skill 替你造选项，再一路问到你真正卡住的地方。

## 为什么做这个

一件事在脑子里转了大半年，什么进展都没有。别人问起，你说"还在想"；过俩月再问，还是"还在想"。不是不上心，是每次一想到这件事，脑子里弹出来的都是同一句没头没尾的话。这个时代的我们生活在一个每天都在经历快速迭代和变化的环境中，有多久你没有问过自己"我到底想要什么"了？每每遇到类似需要决策的抽象问题，整个人就卡在那儿，跟对着一张白卷发呆没什么两样。一天一天，事情没有变得更清楚，只是变得更旧了。

真正让你开始说话的那次，往往是有人问了一句具体的："所以你是想要A，还是想要B？"就这一下，你突然什么都想明白了——不是对方替你想的，是这两个字（A、B）把你脑子里本来就有、但你自己够不着的东西给撬了出来。

这不是意志力问题，是格式问题。我们这一代人是被选择题喂大的：从小到大做的题，几乎全是从ABCD里选一个。出了校门进入社会，却突然被要求"独立思考""开放式思考"。考卷从选择题换成了问答题，但没人告诉过我们这题该怎么答。

大部分"想不清楚"不是思考能力问题，是缺脚手架。这个skill为你搭好脚手架（具体选项），通过苏格拉底式的诘问法，帮助你更好地理清思路，搞清楚"我到底想要什么"。

## 这套逻辑从哪来的

**核心是苏格拉底的产婆术（maieutics）。** 苏格拉底管自己这套方法叫"精神助产术"——他从不直接给对话者答案，因为他相信答案本来就在对方心里，只是没被"接生"出来。这个skill的整套问答逻辑，做的就是这件事：不是替你生成一个陌生的结论，而是通过一轮轮提问和你的选择，把你心里本来就有、只是自己够不着的想法引出来。具体到"诊断"这一步，用的是产婆术里最关键的一招——诘问法（elenchus）：不断追问，直到你自己的回答之间露出矛盾，那个矛盾暴露的瞬间，就是真正的洞察发生的地方。苏格拉底不会告诉你"你错了"，是你自己在自己的回答里发现答案。

**但纯苏格拉底式的开放追问，放在这里会失效。** 柏拉图笔下的对话是开放式的，明确的，对方要自己组织语言回应。这恰恰是困扰很多人的痛点。我们不是没有想法，是我们无法用语言去描述自己内心的想法和感受。J.P. Guilford 在1950年代提出的"聚合思维（convergent thinking）"与"发散思维（divergent thinking）"的区分说明了原因：我们大多数人的教育经历里被反复训练的是聚合思维（从已知选项里收敛出答案，标准化选择题考的就是这个），发散思维（从零生成想法）基本没怎么练过。所以这个skill把苏格拉底的追问改造成了选择题，即用你更擅长的格式，做同一件事。

**动机性访谈。** "你说自己纠结的是___，但真正卡住的其实是___"，结构上和动机性访谈（Motivational Interviewing，Miller 1983年提出，后与Rollnick共同发展）里的核心技术"发展差异（developing discrepancy）"是同一个逻辑。动机性访谈不给出实际的建议，而是把一个人嘴上的立场，和TA自己回答里暴露出来的真实状况之间的落差摆出来。

**卡在"两个都要"时，退一步问需求，不是硬凑一个新问题。** 当A、B两个选项被逼急了还选不出，问题往往不是选项本身出了错，是两个选项背后各自服务的需求没被看见——这时候会先把"选立场"换成"聊需求"（这是谈判理论里"立场 vs. 利益"的经典做法，出自《Getting to Yes》），需求排出来了，选项往往自己就跟着有了倾向。如果连需求都是平的，才会用几个有心理学依据、而且完全公开透明的技巧从侧面问（比如想象一年后的情绪反应、拿走一个选项测失落感），全程让你清楚知道自己在回答什么，绝不会设计一道你看不出关联的"暗箱测试题"去偷偷猜你的答案——这违背这个skill的根本原则：所有材料必须来自你自己知情的回答，而不是被替你编一套解读。如果两边是真的旗鼓相当，就换用不依赖继续内省的判据（比如哪个选项走错了更容易掉头、后悔感的时间规律——研究显示人们的后悔感有系统性的时间模式，短期内做过的事更让人痛，但拉长时间看，没做过的事往往更让人后悔，Gilovich & Medvec, 1994），而不是硬凑更多问题去制造一种其实并不存在的清晰。

这个skill不是心理治疗，但引用这些心理学理论框架，是为了让skill最终产出有价值的、基于用户与AI间一轮轮提问-选择交互的、只属于你个人的结果。

## skill如何工作

当你被一件"没想清楚"的事卡住时——不管是人生大事（换工作、去留、价值观排序），还是一个具体任务不知道怎么下手（怎么汇报、项目从哪开始）——这个skill会：

1. **先判断问题类型。** 如果你已经有具体选项或具体任务，直接进深挖；如果完全一团雾、连选项都说不出来，会先搭出3-4个具体候选方向，因为有东西可以反应，才是真正启动思考的钥匙。
2. **分两层深挖**，全程尽量用claude自带的、可点选的选项完成（`ask_user_input_v0`），不是甩给你一个空白输入框：
   - **事实层**——背景、受众、目的、现状。
   - **本质层**——至少一整轮，专门往下刨，找到你真正在纠结、不舒服、害怕的是什么。收口的标准不是"信息够了"，而是能不能填出这句话："你表面纠结的是___，但真正卡住的其实是___"，填不出具体答案就还没挖够。
3. **用"角色卡"的格式给结果**，不是一份分析报告：
   - **【LABEL】**——一个一针见血、带点玩梗的类型标签，只从这一次交互里提炼，风格类似MBTI。
   - 一段话讲清楚核心判断，同时带出优点、问题、当前状态。
   - 现在做什么 / 下一步 / 暂时别做什么。
   - 老老实实列出这一轮问了什么、你选了什么。

每次触发都是独立的一次分析——不引用历史对话或存下来的背景信息，因为用这个skill的不一定是同一个人。

## 怎么用

自然描述你卡在哪儿就行，或者直接触发：

```
/elenchus 该不该接这个offer
/elenchus 5    # 把深挖问题数量封顶在5个（默认不设死数，一般至少2轮，最多12个）
```

## 怎么装

1. 下载 [`elenchus.skill`](./elenchus.skill)（或者只拿 `elenchus/SKILL.md` 这一个文件）。
2. 在Claude里进 **设置 → Capabilities → Skills**（不同平台入口命名可能不太一样），上传这个文件。
3. 在任意对话里按上面的方式触发。
